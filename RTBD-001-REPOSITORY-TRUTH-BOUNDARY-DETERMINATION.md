## Section 7 — Root Question: What Constitutionally Defines Repository Truth?

**Q**: Is Repository Truth:
- A. Only tracked canonical artifacts
- B. Tracked canonical artifacts plus deterministically generated constitutional products
- C. Another constitutionally legislated boundary

**Answer: A — with the following precise statement.**

Repository Truth is exactly and only the set of git-tracked, non-ignored, human-authored corpus files of included types, as defined by GOV-005 §5.1 and §5.3.

The deterministically generated products (knowledge/, closure.json, realization/, etc.) are NOT part of Repository Truth. They are **PRODUCTS of Repository Truth**. The distinction is constitutional:

- Repository Truth = the set of facts that are canonical by authorship and version control
- Generated products = derived outputs that can be reconstructed from Repository Truth

Answer B is seductive but incorrect. Including generated products in Repository Truth would create a recursive definition: Repository Truth would depend on products derived from Repository Truth. GOV-005 §5.3 explicitly excludes this: "environment/generated output ≡ non-artifact bounded by version control."

The correct constitutional model is:

```
Repository Truth (tracked, human-authored)
        ↓
Generator code (tracked, human-authored — part of Repository Truth)
        ↓
Generated products (excluded — Type B/C/D, derivable)
```

Repository Truth is self-contained. It contains its own generators. The generators produce the excluded artifacts. No excluded artifact is required as input to Repository Truth or its generators.
