## SECTION 2 — STATUS CALCULATION MODEL

All roll-ups are deterministic functions of the evidence baseline:

1. **Artifact status** = `artifacts.json[i].status` (verbatim), mapped per §1.2(a). `Exists = YES` iff the artifact appears in `artifacts.json` with a resolvable `path`. `Registered = YES` iff it appears in `artifacts.json` (the Universal Artifact Registry). `Frozen = YES` iff status `FROZEN`. `Active = YES` iff status `ACTIVE`. `Superseded = YES` iff listed in `01-WORKING/SUPERSESSION-REGISTER.md` (currently none at artifact-status level). `Certified` is a **program/dimension** property (see rule 4), not an artifact-status value.
2. **Dependencies Closed** = YES iff every ID in `artifacts.json[i].dependencies` resolves to a registered artifact whose status ∈ {ACTIVE, FINAL, FROZEN}. (Repository evidence: IMP and RUN chains explicitly record closed dependency chains.)
3. **Program roll-up** = `control-tower.json.programs[p].rollup_status`, derived from the program's artifact status histogram. FROZEN iff all members FROZEN; otherwise ACTIVE while any member ACTIVE.
4. **Dimension roll-up** = `control-tower.json.dimensions[d].status` (from the append-only signal ledger, UKB-012). A dimension is *satisfied* when COMPLETE (APPROVED/IMPLEMENTED/CERTIFIED).
5. **Portfolio roll-up** = `control-tower.json.portfolio.portfolio_status` (verbatim).
6. **Completion %** = satisfied dimensions ÷ tracked dimensions (see §9), and established artifacts ÷ total artifacts, each reported separately.

No value in this registry is produced by any means other than the six rules above.
