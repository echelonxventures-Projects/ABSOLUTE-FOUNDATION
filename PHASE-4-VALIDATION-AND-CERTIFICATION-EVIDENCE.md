## 7. Pre-existing failures — disclosed, not repaired

Both were measured **at clean `HEAD` with all Phase 4 changes stashed**, so neither is attributable to this phase.

### 7.1 Four `test_verification_intelligence` failures — local environment only

`test_run_tests_executes_every_shard_and_passes_when_they_pass`, `test_run_tests_fails_when_any_shard_fails`, `test_the_floor_is_evaluated_once_over_the_union_of_the_shards`, `test_the_shards_collect_exactly_the_tests_the_whole_suite_collects`.

Cause: these spawn subprocesses passing `--no-cov`, which requires `pytest-cov`. `pytest-cov` is **not installed** in the interpreter used here, so the collection subprocess exits with `unrecognized arguments: --no-cov` and returns an empty set, failing `assert serial`. `verify.sh` builds its own venv with pinned `pytest-cov`, so CI does not have this gap. Verified identical with Phase 4 stashed: **4 failed, 1 passed**.

The bounds 217 and 84 **were** the measured values when those artifacts were generated. The repository has since drifted to 274 and 85.
