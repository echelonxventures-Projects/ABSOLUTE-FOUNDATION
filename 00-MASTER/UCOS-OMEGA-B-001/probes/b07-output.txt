PHASE Ω∞-B PROBE B-07 — removability validation for every BLOCKING and CRITICAL finding.

AUTHORITY = NONE (DERIVED TRUTH). This probe MEASURES. It registers nothing permanently, writes no
governance record, advances no ratchet, issues no certification, seals nothing and modifies no
module in ``engine/``. Every registry it touches is one it constructed itself and discards on exit.

WHY THIS FILE CONTAINS CODE THAT LOOKS LIKE AN IMPLEMENTATION, AND WHY THAT IS NOT A VIOLATION.
The Ω∞-B directive forbids implementing fixes "unless a finding explicitly demonstrates that
implementation is required to validate a hypothesis". Six findings do exactly that, because the
question Ω∞-B must answer about each of them — REMOVABLE, PARTIALLY REMOVABLE or FUNDAMENTAL — is
not decidable by inspection:

    Ω∞-A Deliverable 7 §7 lists five FALSIFICATION CRITERIA for the architectural core. Criterion 1
    is "a governance rule that is not expressible as a composition of guards". Whether that
    criterion fires cannot be established by reading ``state.py``; the only way to learn whether the
    eight governance capabilities B-02 names are expressible as guards is to WRITE the guards and
    see which ones refuse to be written.

So each prototype below is a FALSIFICATION HARNESS, not a fix:

  * it lives outside ``engine/`` and nothing imports it;
  * it composes only over SHIPPED types — if a prototype needed a change to a shipped type, that is
    the finding, and it is reported as one rather than worked around;
  * it is discarded on exit;
  * a prototype that WORKS proves the blocker is implementation-induced and REMOVABLE;
  * a prototype that CANNOT BE WRITTEN over shipped types proves the blocker is architecture-induced
    and reports which shipped type must change.

The distinction that matters: this file does not remove a single blocker. It establishes, with
executable evidence, WHICH KIND each blocker is.
