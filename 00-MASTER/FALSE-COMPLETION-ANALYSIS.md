## FALSE COMPLETION ATTACK VECTORS

### FC-01: VACUOUS VALIDATOR

**Mechanism**: Independent validator exists but validates nothing (always returns PASS)

**Example**:
```python
def validate_artifact(path):
    return True  # vacuous validator
```

**Detection**:
- Validator has no assertions
- Validator reads no authority corpus
- Validator never returns False
- Validator has 100% test pass rate with no negative tests

**Backlog Claims**:
- ✓ W2-{producer}: "Independent validator implemented" (DONE)
- ✓ W3-{producer}: "Attack executed, validator detected" (PASS because validator always passes)
- ✓ W6-{producer}: "CI integration complete" (PASS because validator is vacuous)

**Threat Remains Open**: MB7 (self-validation loop intact)

**Current Exposure**: HIGH (32/33 validators don't exist yet; vacuous implementation would satisfy backlog literally)

**Blocking Mechanism**:

1. **Code Review**: Validator code must have assertions, must read authority, must have logic
2. **Negative Test Requirement**: W3 attack must show `gate_exit=0 AND verifier_exit=1` (requires validator to actually catch)
3. **Line Coverage**: Validator must achieve >80% coverage of authority corpus
4. **Explicit False Path**: Validator must have reachable `return False` path

**Backlog Enhancement**:
- W3 evidence: Add requirement "attack log shows verifier_exit=1"
- W2 evidence: Add requirement "validator contains assertions"

**Risk After Enhancement**: LOW (negative test proves validator is non-vacuous)

### FC-02: SELF-DERIVED PROOF

**Mechanism**: Validator imports and runs the generator to compute expected output, then validates against that

**Example**:
```python
from context_generator import generate_context

def validate_context(path):
    expected = generate_context()  # self-derived
    actual = read_file(path)
    return expected == actual
```

**Detection**:
- Validator imports generator module
- Validator calls generator functions
- Validator has no independent authority source

**Backlog Claims**:
- ✓ W1: "Authority corpus identified" (claims generator code is authority)
- ✓ W2: "Independent validator implemented" (false: validator depends on generator)
- ✓ W3: "Attack detected" (false: uniformly wrong generator makes validator agree)

**Threat Remains Open**: MB7 (circular validation)

**Current Exposure**: MEDIUM (W2 requirement says "does NOT import generator" but no automated enforcement)

**Blocking Mechanism**:

1. **Static Analysis**: Add `scripts/check_validator_imports.py` that scans validator code for generator imports
2. **W2 Gate**: Validator passes static analysis before marking W2 complete
3. **Evidence Enhancement**: W1 evidence must be a standalone `.json` file, not generator code

**Backlog Enhancement**:
- W2 evidence: Add "no generator imports (verified by static analysis)"
- W6: Add check_validator_imports.py to CI

**Risk After Enhancement**: LOW (import scanning is reliable)

- UCOS-UCTX-001 generates its own certification report
- Certification reads generated output to certify generator

**Detection**:
- Certification artifact in `generated-artifact-registry.json` with producer = certified entity
- Certification reads no independent evidence

**Backlog Claims**:

**Threat Remains Open**: Any threat (certification proves nothing)

**Current Exposure**: LOW (certification wave explicitly reads independent evidence from W1-W6)

**Blocking Mechanism**:

1. **Evidence Independence**: W7 must read evidence from W1-W6 (which are independently produced)
2. **Manual Review**: Certification requires human review of evidence chain
3. **Immutable Evidence**: W1-W6 evidence committed before W7 runs

**Backlog Enhancement**:

**Risk**: LOW (architecture already prevents this)

### FC-04: DETECTOR CORRUPTION

**Mechanism**: Validator is correct initially but later modified to pass uniformly wrong output

2. W3: Attacks pass (validator works)
3. W6: CI integration passes
4. Post-certification: Edit validator to be vacuous
5. Generator corruption now undetected

**Detection**:
- Validator file modified after certification
- No governance on validator file
- No re-verification after validator change

**Backlog Claims**:
- ✓ All waves complete at time of certification
- Corruption happens POST-certification

**Threat Remains Open**: MB7 (validator corrupted after closure)

**Current Exposure**: MEDIUM (validators not in CODEOWNERS)

**Blocking Mechanism**:

1. **Governance**: Add validators to CODEOWNERS (require review)
2. **Immutability**: Validators become authority files post-certification
3. **Re-verification**: CI runs all validators always (not just at certification)
4. **Validator Audit**: Periodic re-execution of W3 attacks (regression testing)

**Backlog Enhancement**:
- W0-001: Add validator paths to CODEOWNERS
- W6: CI runs validators on every commit (not just during certification)

**Risk After Enhancement**: LOW (governance + continuous validation)

### FC-12: DETERMINISM FALSE POSITIVE

**Mechanism**: Determinism test passes but generator is actually non-deterministic (test insufficiently sensitive)

**Example**:
- W4D: Run generator twice, outputs identical
- Reality: generator includes timestamp but with 1-second granularity
- Two rapid executions produce identical timestamp (false pass)
- Slower executions would differ

**Detection**:
- Test runs too quickly (sub-second)
- Test doesn't vary environment (timezone, locale, host)
- Test doesn't inspect output for timestamp patterns

**Backlog Claims**:
- ✓ W4D: "Determinism verified"

**Threat Remains Open**: MB23 (non-determinism undetected)

**Current Exposure**: MEDIUM (test implementation not specified)

**Blocking Mechanism**:

1. **Sleep Between Runs**: Determinism test sleeps 2 seconds between runs
2. **Environment Variation**: Run on different hosts/timezones
3. **Timestamp Scanning**: Pre-scan output for timestamp patterns (fail if found)
4. **Multiple Runs**: Execute 3+ times, all outputs must match

**Backlog Enhancement**:
- W4D evidence: "3 runs, 2-second gaps, all byte-identical"

**Risk After Enhancement**: LOW (sensitive test catches non-determinism)
