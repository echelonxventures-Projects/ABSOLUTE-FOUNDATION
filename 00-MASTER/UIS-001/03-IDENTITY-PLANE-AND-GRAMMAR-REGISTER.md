## Why four schemes is the architecture and not a defect

- **P2 — Universal ID Ledger allocator.** The durable plane. Its owner's own AIF conformance amendment declares it realizes AIF-L02 opaque durable identity (P2), so the plane is read from the owner rather than inferred here. UMB-003 §2 constitutionalizes the existing allocator and does not re-create it.
- **P3 — Universal Nomenclature crosswalk.** The admission-ordinal plane. Its owner's own AIF conformance amendment declares it realizes AIF-L04, the witnessed non-recomputable ordinal (P3), and UMB-004 §2 declares that the Nomenclature Engine maintains the crosswalk while renaming a native ID never changes the durable identity.
- **P4 — Universal Registry Platform identity.** A logical-plane key: deterministic over a logical tuple, so the same logical artifact resolves identically regardless of version, clock, machine or registration order. It imports canonical hashing from UCKP Layer Zero rather than redefining it.
- **P4 — UCKP Layer Zero universal identity.** The knowledge-object logical name. Pure and clock-free, so it satisfies AIF-L18 derivation purity.
- **P1 — Knowledge Registry content identity.** A content-plane digest used to recognise corroboration instead of manufacturing a duplicate. Under AIF-L05 a content digest VERIFIES and does not identify, which is exactly the role it plays: it decides sameness of substance, not durable identity.
- **P5 — Universal Context identity.** The runtime/observation plane: a context describes the situation a running system reasons about. CXL-10 declares that context describes and never grants, which is why it cannot be substituted for durable identity.
